# Олимпус — полный проект для GitHub

Начните с [инструкции переноса](docs/GITHUB.md). [Форматы материалов](docs/CONTENT.md) · [Сохранение и резервные копии](docs/STORAGE.md).

Эта версия содержит обновлённый мобильный интерфейс на официальном MAX UI. Файлы package.json и compose.yaml находятся в корне.

Учебное демо для 4–6 классов: математика и информатика. Календарь, база знаний, тренировки, пробники, профиль. React + официальный @maxhub/max-ui, серверный API и SQLite/D1. Контент: 72 темы, 360 уроков, 360 заданий, 6 демонстрационных олимпиад и 6 пробников. Демо-события не являются объявлениями реальных организаторов.

## Запуск

Установите Docker с Compose и выполните `docker compose up --build`. Откройте http://localhost:3000. База и загруженные файлы сохраняются в томе `olympus_data`; не удаляйте его. Для публичного запуска разместите за HTTPS-прокси. Демо-пароль администратора: **1111**, подсказка показана на экране. При необходимости скопируйте `.env.example` в `.env` и заполните переменные. Внешние подключения не нужны для календаря, теории, математических задач, редактора и прогресса.

Для разработки: Node 22+, `corepack enable`, `pnpm install --frozen-lockfile`, `pnpm build`. В этой сборке SQLite и файлы работают локально через Wrangler/Miniflare. Аккаунт Cloudflare или ChatGPT для Docker-запуска не нужен. Сам GitHub Pages не запускает сервер и базу: потребуется серверный хостинг или Docker.

## Как добавлять материалы

Через интерфейс: «Админ» → пароль 1111 → нужный тип материала → «Добавить». Доступны черновик, предпросмотр, публикация и история. «Удалённые» позволяет вернуть материал. Изменения записываются в базу сразу после сохранения, без пересборки.

Через GitHub: поместите JSON в `content/ТИП/imports/` и запустите новую сборку. Типы: `olympiads`, `topics`, `lessons`, `tasks`, `mock-tests`. В каждой папке `initial.json` — рабочие примеры схемы. В файле допустим объект или массив объектов. Сохраняйте `id` при обновлении материала. Внутри одного файла ID должны быть уникальны. Файлы imports применяются после initial, в алфавитном порядке; при совпадении ID последняя запись заменяет предыдущую. Файл с неверным JSON остановит сборку. Папки imports уже предусмотрены.

Меняются только записи с изменённым содержимым JSON: неизменённые исходные материалы не затирают правки администратора при очередном развёртывании. Изменённый JSON при следующем запуске становится новой опубликованной версией этого ID. Старые версии сохраняются. Удаление файла из репозитория само по себе не удаляет запись из базы — для этого используйте админку. Импорт JSON через админку работает сразу; экспорт позволяет забрать изменения в репозиторий. Эти два хранилища не синхронизируются автоматически обратно в GitHub.

Поля связей: `topicId` у урока/задания ссылается на тему; `taskIds` пробника — список ID задач. `grade`: 4/5/6, `subject`: math/info. Порядок: `order`. У задачи `type`: number/proof/code, обязательны `prompt` и `solution`; number требует `answer`, code — `tests:[{input,output}]`. Числовые ответы не должны быть записаны в HTML: проверка происходит на сервере. Пример ввода/вывода для ребёнка: `example:{input,output}`. Баллы `points` по умолчанию 1. Блок урока: `{type,value,caption?}`; типы text/example/list/table/formula/code/image/video/link. Таблицы: строки с разделителем `|`, формулы — LaTeX.

## Что сохраняется

Просмотренные уроки, звёзды, уникальные верные задачи, черновики кода, регистрации и все попытки пробников. Повторное правильное решение не даёт вторую медаль за ту же задачу. Достижения сохраняются после удаления материала. Гость узнаётся по cookie браузера; удаление cookie теряет доступ к гостевому прогрессу. Вход через MAX связывает прогресс с проверенным ID и позволяет открывать его на другом устройстве. Абсолютное «навсегда» требует эксплуатации сервера, резервных копий и сохранности тома/БД.

После дедлайна регистрации карточка остаётся с красным статусом. На следующий день после проведения (московская дата) запись и регистрации удаляются из базы при следующем обращении к календарю/API. Это очистка при запросе, а не настроенный отдельный ночной планировщик.

## MAX

SDK загружается с `https://st.max.ru/js/max-web-app.js`. Сервер проверяет HMAC подпись initData и срок действия, принимает имя/фото и идентификатор. Для реальной проверки нужен BOT_TOKEN выданного бота и URL мини-приложения, настроенный в MAX. Токен хранится только на сервере. Сейчас токен не предоставлен: вход и синхронизация MAX не проверены в настоящем клиенте. Возраст не запрашивается.

## Шесть языков

Редактор: Python, C++, Java, JavaScript, Kotlin, Pascal. Запуск через изолированный внешний Judge0 CE, никогда через eval или shell основного сайта. Папка `runner` содержит HTTP-адаптер: он получает доступные версии языков с вашего сервера, выполняет скрытые тесты с лимитами и возвращает результат. В `.env` укажите JUDGE0_URL, при необходимости JUDGE0_AUTH_TOKEN, общий случайный RUNNER_TOKEN, RUNNER_URL=http://runner:8080 для Docker. Запуск адаптера: `docker compose --profile code up --build`. Сам Judge0 нужно развернуть отдельно по официальной документации https://ce.judge0.com/ или использовать разрешённый хостинг. В опубликованном демо он не подключён: редактор сохраняет код, но не имитирует успешную проверку. Подключение требует настройки HTTPS-адреса адаптера и RUNNER_TOKEN на хостинге. Компиляция шести языков в этой среде не проверялась.

## Перед сдачей хакатона

Подключить выданного бота и открыть Mini App в мобильном/веб MAX; проверить профиль на двух устройствах. Подключить sandbox, проверить все языки. Заменить учебные события реальными записями. Провести предметную редактуру подготовленных материалов. Указать оператора и корректные документы обработки данных перед сбором реальных данных детей. Для закрытого демо пароль 1111 согласован; для рабочего приложения выключить DEMO_MODE и задать ADMIN_PASSWORD. Проверить актуальные правила хакатона и лицензии, подготовить презентацию и зафиксировать commit к дедлайну. Подключение UI Kit само по себе не подтверждает полное соответствие всем условиям конкурса.
