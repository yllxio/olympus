# Как сохраняются данные

| Что | Где |
| --- | --- |
| Код, дизайн, JSON, картинки из public/materials | GitHub после Commit + Push |
| Правки админки, опубликованные материалы, черновики и история | Серверная база |
| Звёзды, решения, регистрации, код, попытки пробников | Серверная база |
| Загруженные через админку изображения | Серверное хранилище файлов |
| Токены и пароль администратора | Серверные переменные окружения, не GitHub |

Обновление страницы не очищает базу. Пересборка приложения сохраняет прогресс при использовании того же постоянного тома. «Навсегда» зависит от сохранности сервера и резервных копий. Удаление тома, смена сервера без переноса базы или очистка диска уничтожат данные независимо от GitHub.

## GitHub и админка вместе

- Новые и изменённые JSON применяются при сборке и следующем обращении к API
- Неизменённые JSON не перезаписывают правки, сделанные через админку
- Изменив JSON для существующего ID, вы публикуете его новую версию при следующем деплое; она заменит серверную версию и её черновик. История сохраняется
- Прогресс хранится отдельно и не сбрасывается при этом. Если полностью заменить смысл задания, сохранив ID, ранее заработанное достижение останется связано с этим ID
- Удаление JSON-файла не удаляет уже импортированный материал из базы. Для удаления используйте админку
- Старые олимпиады удаляются при следующем обращении к API после дня проведения, вместе с регистрациями. Просроченный дедлайн только меняет статус
- Админка НЕ делает автоматических GitHub-коммитов

Чтобы сохранить опубликованные правки админки в GitHub: откройте по очереди разделы «Темы», «Уроки», «Задания», «Олимпиады», «Пробники» → JSON. Положите файлы в соответствующие `content/.../imports/`, например `zz-admin-export.json`. Перед экспортом опубликуйте нужные черновики. JSON-кнопка экспортирует опубликованное содержимое, а не историю и не прогресс. Загруженные файлы по ссылкам `/api/media/...` нужно переносить отдельно вместе с хранилищем файлов.

Файлы в imports применяются после initial.json в порядке имён. Если несколько файлов содержат один ID, выигрывает последний по порядку. Для дальнейшего редактирования выбирайте именно выигравший файл, иначе более поздний импорт перекроет ваши изменения.

## Резервная копия Docker-версии

Выполняйте на сервере в папке проекта. На время копирования сайт останавливается, чтобы база и файлы копировались согласованно:

```sh
mkdir -p backups
docker compose stop web
docker compose run --rm --no-deps --entrypoint tar -v "$PWD/backups:/backup" web -czf /backup/olympus-state.tar.gz -C /app/.wrangler/state .
docker compose start web
```

Проверьте, что архив создан и команда завершилась без ошибок. Скопируйте архив на другой защищённый диск. Команда перезаписывает предыдущий архив, поэтому перед следующим запуском сохраните его с датой. `.env` сохраните отдельно в защищённом месте. Папка backups исключена из Git. В копии есть пользовательские данные и сессии — её нельзя публиковать в репозитории.

## Восстановление на НОВОМ пустом сервере

Скопируйте код, `.env` и архив в `backups/`. Восстанавливайте на той же версии приложения, на которой сделана копия:

```sh
docker compose build web
docker compose run --rm --no-deps --entrypoint tar -v "$PWD/backups:/backup:ro" web -xzf /backup/olympus-state.tar.gz -C /app/.wrangler/state
docker compose up -d web
```

Не распаковывайте копию поверх работающей базы или непустого тома: сначала сделайте отдельную копию текущего состояния и подготовьте пустой том. Проверьте материалы, профиль, попытки и изображения до переключения пользователей.

Доступ с любого устройства требует входа через MAX. Гостевой прогресс привязан к cookie браузера. Токен MAX пока не подключён. Запуск программ на шести языках требует отдельного Judge0: адаптер в runner уже включён, сам сервис не разворачивается этим архивом.

Документация Docker: https://docs.docker.com/engine/storage/volumes/
