# Перенос в GitHub — по шагам

## 1. Сохранить проект

1. Распакуйте весь ZIP в папку на компьютере
2. Установите GitHub Desktop: https://desktop.github.com/ и войдите в свой GitHub
3. File → New repository: имя `olympus`, выберите место на компьютере → Create repository
4. Repository → Show in Explorer откроет созданную папку
5. Скопируйте ВНУТРЬ неё содержимое распакованного ZIP, включая файлы с точкой в начале имени. Не переносите всё одной вложенной папкой
6. В корне должны находиться `package.json`, `README.md`, `compose.yaml`, а рядом папки `app`, `content`, `scripts`
7. В GitHub Desktop в Summary напишите «Олимпус — первая версия», нажмите Commit to main
8. Нажмите Publish repository. Оставьте Keep this code private включённым: учебные ответы тоже есть в исходниках. Нажмите Publish repository

Теперь код и материалы хранятся в вашем GitHub. Архив не содержит прежний Git-репозиторий или привязку к аккаунту ChatGPT.

## 2. Где редактировать

В GitHub откройте `content`, нужную папку, затем JSON-файл → значок карандаша → исправьте → Commit changes. Новый файл: Add file → Create new file или Upload files. Форматы подробно описаны в CONTENT.md.

В GitHub Desktop перед локальными изменениями нажмите Fetch origin → Pull origin, чтобы забрать правки с сайта GitHub. После локальных изменений: Commit to main → Push origin.

Не меняйте ID существующей темы/урока/задачи. ID связывает материал с прогрессом. Для нового материала нужен новый ID.

## 3. Как изменения попадут на сайт

Запись в GitHub сама по себе не меняет уже работающий сайт. На сервере нужно получить свежий код и пересобрать приложение:

```sh
git pull --ff-only
docker compose up -d --build web
```

Эти команды выполняются в папке проекта НА СЕРВЕРЕ, где уже настроены Docker, HTTPS и постоянное хранилище. Автоматический деплой из GitHub пока не настроен: сервер и аккаунт хостинга вы ещё не выбрали.

Перед выкладкой можно проверить JSON на компьютере с Node 22+:

```sh
node scripts/compile-content.mjs
```

В репозитории также есть GitHub Actions: проверка JSON запускается после каждого Push и Pull request. Её результат виден во вкладке Actions; сама по себе она не публикует сайт и не запрещает коммит в main.

Проверка не требует установки зависимостей. Она остановится, если, например, пробник ссылается на несуществующую задачу.

## 4. Первый запуск сервера

Нужен Docker-хостинг или Linux-сервер с постоянным диском, не GitHub Pages. Скопируйте проект, создайте `.env` по `.env.example`, затем:

```sh
docker compose up -d --build web
```

Приложение слушает порт 3000. Для доступа в интернете настройте домен и HTTPS на хостинге. База и загруженные через админку файлы лежат в Docker-томе, отдельно от исходников. Не запускайте копии с независимыми дисками, если ожидаете общий прогресс.

Название Compose-проекта зафиксировано как `olympus`, том стандартного запуска — `olympus_olympus_data`. Если вы УЖЕ запускали старый ZIP, сначала сохраните его том и настройте использование именно этого тома. Новый пустой том не содержит старых данных.

## 5. Что переносится этим ZIP

Полный код актуального интерфейса MAX UI, 804 подготовленных материала, серверная логика сохранения, схема базы, адаптер проверки кода, инструкции.

Это исходный проект, НЕ выгрузка живой базы опубликованного сайта. Существующие пользовательские попытки, сессии, правки админки и загруженные файлы с прежнего хостинга в архив не включены. Не выключайте прежний сайт до отдельного переноса и проверки этих данных. Из админки можно забрать опубликованные материалы кнопкой JSON для каждого из пяти разделов; прогресс и файлы требуют отдельного экспорта базы и хранилища у прежнего хостинга.

При смене домена гостевая cookie не переносится: гость не получит старую сессию автоматически. MAX-профиль на другом устройстве узнаётся по MAX ID только после подключения BOT_TOKEN и переноса соответствующей базы. Реальный вход MAX пока требует настройки и проверки.
